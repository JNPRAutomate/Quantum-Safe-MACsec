## Scope and exact entry points

The implemented top-level commands are **create, bootstrap, deploy, clean, validate**. There is no top-level QKD `start`, `status`, `rotate`, `diagnose` or `stop` command. The router op script and the transport-specific CLIs expose some of those operations separately; do not infer additional commands from introductory comments. Sources: `qkd_orchestrator.py:252`, `qkd_orchestrator.py:2033`, `lib/qkd/tcp_ao_cli.py:18`, `artifacts/qkd_onbox.py:7911`.

```text
python3 qkd_orchestrator.py --version
python3 qkd_orchestrator.py create --inventory NAME_OR_PATH [CREATE_OPTIONS]
python3 qkd_orchestrator.py bootstrap [BOOTSTRAP_OPTIONS]
python3 qkd_orchestrator.py deploy [DEPLOY_OPTIONS]
python3 qkd_orchestrator.py validate [--phase predeploy|postdeploy|full] [-v ...]
python3 qkd_orchestrator.py clean [CLEAN_OPTIONS]
```

This is invocation documentation, not a record of commands executed during this analysis. Parser evidence: `qkd_orchestrator.py:252`, `qkd_orchestrator.py:301`, `qkd_orchestrator.py:357`, `qkd_orchestrator.py:400`, `qkd_orchestrator.py:477`, `qkd_orchestrator.py:517`.

### Important distinction: router, local controller and KME host

QKD `create` writes the controller's runtime inventory, artifacts and PKI; it does not build or deploy KME containers. QKD `deploy` writes router files and Junos configuration; KME host changes belong to `kme_orchestrator.py`. `create` prints manual KME certificate copy instructions rather than performing those copies. Sources: `qkd_orchestrator.py:1284`, `qkd_orchestrator.py:1315`, `qkd_orchestrator.py:1353`, `qkd_orchestrator.py:1366`, `kme_orchestrator.py:105`.

## Global and inherited inputs

- Repository paths are declared in `CONFIG`: `config/runtime`, `config/inventory/input`, `config/templates`, `artifacts`, `certs/self_signed`, `certs/hierarchical_ca`. Relative common-config loads are rooted at the repository, but not every low-level helper uses the same path policy; run from the repository root. Sources: `lib/common/settings.py:1`, `lib/common/config.py:22`, `lib/qkd/inventory_builder.py:65`, `lib/qkd/pki_self_signed.py:312`.
- The default base inventory is fixed at `config/inventory/inventory_base.yaml`; its current script account is `admin`, not the fallback `etsi_user`. The environment can override that account. Sources: `lib/common/config.py:50`, `config/inventory/inventory_base.yaml:3`, `lib/common/script_user_bootstrap.py:139`.
- Runtime devices are read from `config/runtime/devices.yaml` under `devices`; topology comes from `topology.yaml`, PKI selection from `pki_profile.yaml`, policy from `qkd_policy.yaml`. These are shared mutable outputs, not independent per-inventory namespaces. Sources: `lib/common/config.py:60`, `lib/common/config.py:65`, `lib/common/config.py:69`, `lib/common/config.py:127`, `qkd_orchestrator.py:1051`.
- `--help` is generated by argparse, but the QKD main function enters output capture before parsing. Even a help/version run can write a timestamped controller log in the hard-coded log directory. This analysis therefore reads parser code instead of launching the CLI. Sources: `qkd_orchestrator.py:2033`, `lib/common/command_output.py:13`, `lib/common/command_output.py:44`.

### Credential precedence and environment knobs

Administrative username resolution: explicit override → `QKD_BOOTSTRAP_USER` → `secrets.bootstrap_user` → `secrets.deploy_user` → `QKD_DEFAULT_USER` → `secrets.default_user` → interactive prompt. Administrative password resolution: `QKD_BOOTSTRAP_PASSWORD` → `secrets.bootstrap_password` → `secrets.deploy_password` → `secrets.root_password` → `QKD_DEFAULT_PASSWORD` → `secrets.default_password` → non-echoing prompt. Values are deliberately not reproduced here. Sources: `qkd_orchestrator.py:1074`, `qkd_orchestrator.py:1090`.

Script account: explicit library override → `QKD_SCRIPT_USER` → `secrets.script_user` → `QKD.SCRIPT_USER` → `etsi_user`. Class: explicit library override → `QKD_SCRIPT_USER_CLASS` → `secrets.script_user_class` → setting → `super-user`. Authentication mode: explicit override → `QKD_SCRIPT_USER_AUTH_MODE` → `secrets.script_user_auth_mode` → `password`; aliases `key`, `pubkey`, `public-key` normalize to `key-only`. Current base YAML selects `key-only`. Sources: `lib/common/script_user_bootstrap.py:139`, `lib/common/script_user_bootstrap.py:152`, `lib/common/script_user_bootstrap.py:189`, `config/inventory/inventory_base.yaml:9`.

Script password: explicit library override → `QKD_SCRIPT_PASSWORD` → `secrets.script_password` → `secrets.admin_password` → `QKD_DEFAULT_PASSWORD` → `secrets.default_password`. Upload transport is independent: CLI `--upload-user`, then `QKD_UPLOAD_USER`, then administrative account; `QKD_UPLOAD_PASSWORD` or a separate prompt when the upload account differs. Sources: `lib/common/script_user_bootstrap.py:165`, `qkd_orchestrator.py:1138`, `qkd_orchestrator.py:1670`, `qkd_orchestrator.py:623`.

`QKD_BOOTSTRAP_VERBOSE` accepts `1`, `true`, `yes`, `on` for bootstrap shell output. Not every setting in `QKD` is an environment variable: the exhaustive environment rows in the matrix list actual environment reads rather than inventing environment names for dictionary constants. Source: `lib/common/script_user_bootstrap.py:746`.

## `create`: ordered behavior

Purpose: turn a human link-driven inventory into the exact runtime contract consumed by provisioning, PKI and the on-box agent. It is a **local generation operation**, although credential prompts can occur. Sources: `qkd_orchestrator.py:1165`, `qkd_orchestrator.py:1284`, `qkd_orchestrator.py:1315`.

1. Resolve explicit path from cwd, then repository-relative path, then `config/inventory/input/<name>.yml`, then `.yaml`. `.yml` wins a same-name tie. Sources: `lib/common/config.py:89`, `lib/common/config.py:100`, `lib/common/config.py:109`.
2. Require a mapping with nonempty `devices`, top-level `topology`, `platform`, `mode`; support list and dictionary device forms. Reject generated `ring`, `chain`, `pair`, `hub`; `links`/`explicit` require a nonempty `links` list. Reject overlapping IDs between `links` and `extra_links`. Sources: `qkd_orchestrator.py:167`, `qkd_orchestrator.py:218`, `qkd_orchestrator.py:1169`, `qkd_orchestrator.py:1180`, `qkd_orchestrator.py:1192`.
3. Select PKI: CLI `--pki-profile` → source `pki_profile` → `self_signed`. Load base secrets and resolve the script user. Resolve global administrative credentials if any input device lacks both inline `auth` and base per-device `auth`. Source: `qkd_orchestrator.py:1199`.
4. **Delete all non-hidden contents of `config/runtime` before all device records have been validated.** A later invalid device or policy can leave the old runtime destroyed and a new runtime only partly built. Hidden files are preserved. Source: `qkd_orchestrator.py:1219`, `qkd_orchestrator.py:1051`.
5. Per device, require `name`, `ip`, `kme`, `interfaces`; interfaces must be a nonempty list; names must be unique. Credentials: inline `auth` → base `devices.<name>.auth` → global credentials. KME accepts a string or mapping with `ip`/`address`; port accepts device mapping `port`, otherwise base `kme.port`, otherwise `443`. Source: `qkd_orchestrator.py:1224`, `qkd_orchestrator.py:185`.
6. Derive SAE IDs from prefix/separator/padding and input order unless explicitly provided. Preserve hostname, SSH trust, management address, QKD metadata, managed status and the enumerated metadata fields. Normalize KME into canonical mappings and build runtime topology/devices. Sources: `qkd_orchestrator.py:89`, `qkd_orchestrator.py:1250`, `qkd_orchestrator.py:1263`, `lib/qkd/inventory_builder.py:139`.
7. Assign link side A as `master`, side B as `slave`; a single device can have both roles on different links. Exclude unmanaged nodes from runtime devices, while retaining their peer metadata in topology. Sources: `lib/qkd/topology_builder.py:474`, `lib/qkd/topology_builder.py:515`.
8. Write inventory, topology, PKI profile and policy outputs; policy is a deep copy of the policy template with only non-`None` CLI overrides. Static mode generates one shared static CAK/CKN pair for the runtime devices; QKD mode does not generate operational quantum keys here. Sources: `qkd_orchestrator.py:1284`, `lib/qkd/inventory_builder.py:106`, `lib/qkd/inventory_builder.py:119`, `lib/qkd/inventory_builder.py:452`, `lib/qkd/inventory_builder.py:506`.
9. Build per-managed-QKD-device script and two JSON sidecars. Static mode intentionally has no on-box script output. Sources: `qkd_orchestrator.py:1315`, `lib/qkd/onbox_builder.py:389`.
10. Calculate PKI signature from sorted runtime device names, SAE IDs, KME IPs/ports and unique KME addresses. Reuse PKI only when profile-specific marker exists and signature matches; otherwise regenerate, persist `.runtime_signature.json`, print manual KME copy instructions. The signature does not include every certificate policy, validity, router address or source profile field, so changing such a field need not trigger renewal. Sources: `qkd_orchestrator.py:113`, `qkd_orchestrator.py:1325`, `qkd_orchestrator.py:1350`.

### Re-run and failure semantics

`create` is not a non-destructive reconciliation command: runtime is cleared, static secrets can change, and PKI can regenerate on signature changes. It does not roll back generated files if a later stage fails, and does not remove stale router files or containers. Complete remote clean should be done while the old runtime still identifies targets. Sources: `qkd_orchestrator.py:1051`, `lib/qkd/inventory_builder.py:106`, `qkd_orchestrator.py:1353`, `lib/qkd/clean.py:923`.

## `bootstrap`: ordered behavior and all options

Purpose: create/fix the script runtime account and its controller/router SSH identities before deployment. It reads runtime devices and base identity/credential settings; it does not generate topology or PKI. Sources: `qkd_orchestrator.py:1386`, `lib/common/script_user_bootstrap.py:1204`.

1. Load runtime and base inventory; resolve administrative credentials, except dry-run avoids the interactive administrative prompt. Sources: `qkd_orchestrator.py:1386`, `qkd_orchestrator.py:1393`, `qkd_orchestrator.py:1428`.
2. Filter eligible managed devices; resolve script user, class, authentication mode and RPC key name. In key-only mode ensure a controller script-user keypair, mirror it into the current account's SSH directory, and write SSH aliases for real runs. **The keypair generation/mirroring happens before the dry-run guard**, so bootstrap dry-run is not completely free of local file changes. Sources: `lib/common/script_user_bootstrap.py:1236`, `lib/common/script_user_bootstrap.py:1253`.
3. Configure login account/class and authentication. Password mode only sets an encrypted password for a newly created account; key-only mode adds the selected public key and can remove encrypted-password authentication. Fix home/SSH modes and install runtime and RPC key material using privileged transport. Sources: `lib/common/script_user_bootstrap.py:609`, `lib/common/script_user_bootstrap.py:685`, `lib/common/script_user_bootstrap.py:823`, `lib/common/script_user_bootstrap.py:1040`.
4. Collect successful/failed devices. Top-level bootstrap prints partial success and next steps rather than raising merely because some devices failed; deploy later relies on actual predeploy checks, not a durable bootstrap-success filter stored here. Sources: `qkd_orchestrator.py:1443`, `qkd_orchestrator.py:1453`, `qkd_orchestrator.py:1757`.

| Option | Default | Actual scope |
|---|---|---|
| `--dry-run` | `false` | No router mutations intended; local key preparation can still occur. `qkd_orchestrator.py:364`, `lib/common/script_user_bootstrap.py:1253`. |
| `-v`, `--verbose` (repeatable) | `0` | Passed into bootstrap helper/logger. `qkd_orchestrator.py:369`, `qkd_orchestrator.py:1423`, `qkd_orchestrator.py:1450`. |
| `--bootstrap-user USER` | `None` | Administrative credential override. `qkd_orchestrator.py:372`, `qkd_orchestrator.py:1431`. |
| `--ssh-key PATH` | `None` | Accepted by parser but not used by `handle_bootstrap`; cannot assume it changes the generated runtime identity. `qkd_orchestrator.py:381`, `qkd_orchestrator.py:1377`. |
| `--debug` | `false` | Accepted but not read in the bootstrap handler; use actual verbose mechanisms. `qkd_orchestrator.py:382`, `qkd_orchestrator.py:1377`. |

## `deploy`: ordered behavior

Purpose: publish the current router agent and sidecars, install PKI, apply MACsec or selected TCP-AO configuration, and check runtime health. Bootstrap is a separate prerequisite, despite older comments or progress labels suggesting otherwise. Sources: `qkd_orchestrator.py:1470`, `qkd_orchestrator.py:1757`, `qkd_orchestrator.py:1820`, `qkd_orchestrator.py:1864`.

1. Validate mode combinations. `--onbox-only` conflicts with `--shipment-preload`. BGP AO requires both `--keys` and `--timers`; LDP AO requires both `--ldp-keys` and `--ldp-timers`; those numeric options are invalid without the corresponding enable flag. AO conflicts with preload/onbox-only. Source: `qkd_orchestrator.py:1479`.
2. Load runtime devices and base settings. Load requested AO settings and/or active persisted AO settings even during otherwise ordinary deploy. Protocol wrappers can restrict targets to selected-session endpoint names. Persisted AO state can consequently affect future deploys after runtime regeneration. Sources: `qkd_orchestrator.py:1505`, `qkd_orchestrator.py:1516`, `qkd_orchestrator.py:1528`, `qkd_orchestrator.py:1546`, `qkd_orchestrator.py:1551`.
3. For requested AO preview/dry-run, print a local plan and return before router discovery, KME calls or commits; ordinary preview/dry-run calls provisioning with `dry_run=True` and optionally renders statement text. Sources: `qkd_orchestrator.py:1601`, `qkd_orchestrator.py:1632`, `qkd_orchestrator.py:1650`.
4. For real deploy resolve administrative/upload credentials and script mode. In key-only mode ensure/mirror the local runtime key and write controller SSH aliases. In password mode require script password. Set in-memory device NETCONF credentials to administrative transport for prechecks. Source: `qkd_orchestrator.py:1661`, `qkd_orchestrator.py:1692`, `qkd_orchestrator.py:1713`, `qkd_orchestrator.py:1723`.
5. Unless skipped, run **destructive** predeploy identity checks. Drop failing devices; fail if none remain. For password-mode deployments switch remaining in-memory auth to script user after the checks; key-only keeps administrative NETCONF/SCP transport. Source: `qkd_orchestrator.py:1743`, `qkd_orchestrator.py:1757`, `qkd_orchestrator.py:1767`.
6. Refresh artifacts from the checked-in `artifacts/qkd_onbox.py`, even without rerunning `create`. Source: `qkd_orchestrator.py:1788`, `lib/qkd/onbox_builder.py:325`.
7. Upload script and sidecars into PID-suffixed staging files under `/var/tmp` as upload user; install as privileged bootstrap user. Connect using NETCONF port `830`, falling back to `22` in this installer. Source: `qkd_orchestrator.py:610`, `qkd_orchestrator.py:710`, `qkd_orchestrator.py:737`, `qkd_orchestrator.py:988`.
8. Create op/event directories and shared peer-status directory; script copies are root-owned mode `555`; config JSON is script-user-owned `600`; inventory JSON is script-user-owned `640`; directory modes are set explicitly. Remove obsolete sidecars/staging names. Synchronize script and sidecars to passive RE where detected. Sources: `qkd_orchestrator.py:748`, `qkd_orchestrator.py:773`, `qkd_orchestrator.py:798`, `qkd_orchestrator.py:1031`.
9. AO requested: register op script, distribute RPC trust and push certificates during installation; skip MACsec provisioning. Preload or onbox-only: skip QKD provisioning. Otherwise per managed device with runtime links: load platform YAML, render static or QKD config, push certificates, commit script/event account configuration, commit MACsec config, then distribute peer public keys. Sources: `qkd_orchestrator.py:1022`, `lib/qkd/provisioning.py:941`, `qkd_orchestrator.py:1834`, `qkd_orchestrator.py:1852`, `lib/qkd/provisioning.py:1121`, `lib/qkd/provisioning.py:1256`.
10. Requested AO: invoke master op `bgp-tcp-ao-start` / `ldp-tcp-ao-start`, require exact success marker, mark settings active locally. Source: `qkd_orchestrator.py:1875`, `qkd_orchestrator.py:1895`.
11. Unless skipped or preload, run postdeploy identity/runtime checks. Print execution summary. Provisioning failures are accumulated and printed but are **not raised by `run_provisioning` itself**; a summary saying deploy completed is not proof every device committed successfully. Sources: `qkd_orchestrator.py:1915`, `qkd_orchestrator.py:1933`, `lib/qkd/provisioning.py:1299`.

### Router configuration statement families

Normal QKD rendering deletes/recreates named authentication keychains; resets fallback keys; optionally sets deterministic fallback `ckn`/`cak`; otherwise seeds slot 0 and deletes stale slots 1..5. It sets `cipher-suite gcm-aes-xpn-256`, `security-mode static-cak`, `replay-protect`, interface-to-CA and CA-to-keychain bindings. This active QKD branch hardcodes the cipher instead of taking platform `macsec.cipher`. Sources: `lib/qkd/rendering.py:158`, `lib/qkd/rendering.py:169`, `lib/qkd/rendering.py:181`, `lib/qkd/rendering.py:226`.

### Idempotence, rollback and availability

- Redeploy is a **reset/bootstrap**, not guaranteed hitless reconciliation: prechecks delete JSON state and rendered MACsec resets keychains/fallback. `--onbox-only --skip-pre-validation` avoids those two normal reset paths, but still rewrites sidecars/scripts and can run postdeploy status. Sources: `lib/qkd/identity.py:499`, `lib/qkd/rendering.py:169`, `qkd_orchestrator.py:1834`.
- Certificates/scripts are copied before configuration commits; script registration and MACsec use separate commits. A later error does not undo earlier file copies or commits. Sources: `lib/qkd/provisioning.py:1139`, `lib/qkd/provisioning.py:800`, `lib/qkd/provisioning.py:1163`.
- Candidate rollback 0 is performed during script setup, potentially discarding preexisting uncommitted candidate edits. There is no whole-fleet transaction. Sources: `lib/qkd/provisioning.py:707`, `lib/qkd/provisioning.py:735`, `lib/qkd/provisioning.py:1266`.
- Lock contention retries six times with five-second delays around apply. Dual-RE commits use synchronize where detected, retry propagation failures, and can fall back to active-RE local commit. A specific remote-RE L3-VPN license warning is treated as benign; this is **not** general MACsec/TCP-AO license detection. Sources: `lib/qkd/provisioning.py:1145`, `lib/qkd/provisioning.py:309`, `lib/qkd/provisioning.py:329`, `lib/qkd/provisioning.py:354`.

## `validate`: readiness versus health, not read-only

Syntax: `python3 qkd_orchestrator.py validate [--phase predeploy|postdeploy|full] [-v ...]`; phase default `predeploy`, verbose count default `0`. It loads runtime/base credentials, fixes in-memory script identity, and calls `validate_all_devices`; there is no CLI `--dry-run` for validate. Sources: `qkd_orchestrator.py:517`, `qkd_orchestrator.py:1949`, `qkd_orchestrator.py:2010`.

**Predeploy** checks account, home and script directories, SSH identity and authorized keys, then removes state/log/lock files both in script home and legacy staging locations. Legacy QFX takes a reduced check set but still invokes cleanup. Thus never use predeploy/full as a passive health monitor on an operating keyring. Sources: `lib/qkd/identity.py:1095`, `lib/qkd/identity.py:499`.

**Postdeploy** checks op/event file presence/modes, timestamp protocol, Python 3 and event user, deployed JSON identity/policy, keychain slot count, runtime status, and state-save errors. Legacy QFX postdeploy returns success without those checks. Runtime status can reconcile/promote and save state: postdeploy is also not strictly read-only. Sources: `lib/qkd/identity.py:1119`, `lib/qkd/identity.py:971`, `artifacts/qkd_onbox.py:6654`, `artifacts/qkd_onbox.py:6815`.

**Full** runs both phases; it inherits predeploy destruction before assessing postdeploy health. Phase dispatch: `lib/qkd/identity.py:1237`.

## `clean`: deletion boundary, ordered behavior and every option

Syntax: `python3 qkd_orchestrator.py clean [--local-only] [--pki] [--full-macsec] [--continue-on-failure] [--bootstrap-user USER]`. All boolean defaults are false; administrative override defaults `None`. Sources: `qkd_orchestrator.py:477`, `qkd_orchestrator.py:485`, `qkd_orchestrator.py:2033`.

1. `--local-only`: remove non-hidden runtime contents; additionally remove non-hidden `certs` contents only with `--pki`; return without router access. Source: `lib/qkd/clean.py:904`.
2. Otherwise discover targets from runtime `devices.yaml`, falling back to **base inventory devices**, not the original input YAML, if runtime is gone. Resolve privileged cleanup credentials; preserve original auth as fallback, inject base secrets. Source: `lib/qkd/clean.py:923`, `lib/qkd/clean.py:944`.
3. Per router derive interface/CA/keychain candidates; remove configuration and local/passive-RE files using shell/CLI helpers; check errors and return success/failure. Sources: `lib/qkd/clean.py:148`, `lib/qkd/clean.py:250`, `lib/qkd/clean.py:382`, `lib/qkd/clean.py:559`.
4. Remote failures normally raise before controller runtime deletion, retaining target knowledge. `--continue-on-failure` explicitly permits deleting local runtime despite remote failures. Source: `lib/qkd/clean.py:993`.
5. Finally clean local runtime and optionally PKI. Source: `lib/qkd/clean.py:1019`.

### What is removed

- **All `event-options`**, not only `QKD`/`QKD_TIMER`; op registrations for current and legacy on-box script names; script user and peer-command user; custom login classes. Built-in classes are protected by the cleanup class filter, but existing accounts with matching names are not protected by provenance. Source: `lib/qkd/clean.py:382`.
- Default cleanup deletes candidate MACsec interfaces/CAs and candidate keychains, plus interface descriptions on those interfaces. Orphan CA discovery supplements candidates. Sources: `lib/qkd/clean.py:205`, `lib/qkd/clean.py:403`, `lib/qkd/clean.py:418`.
- `--full-macsec` deletes **all `security macsec` and all `security authentication-key-chains`**, plus authentication bindings found from enabled sessions in the two default AO profile files. That can affect non-QKD users of authentication keychains. It is not an ownership-filtered cleanup. Source: `lib/qkd/clean.py:398`, `lib/qkd/clean.py:25`.
- On-box op/event script files, two sidecars, legacy copies, shared peer inbox/status/ACK directories, certificate trees, script-user and peer-command-user homes, enumerated state/log/lock paths; passive RE recursive cleanup is attempted where detected. Source: `lib/qkd/clean.py:429`, `lib/qkd/clean.py:559`.
- `--pki` removes generated controller PKI directories/files under `certs`; remote certificates are removed by remote cleanup regardless of `--pki`. Sources: `lib/qkd/clean.py:118`, `lib/qkd/clean.py:448`, `lib/qkd/clean.py:1021`.

### What is not a complete inverse

`clean` does not stop/destroy the Linux KME Compose lab, uninstall Docker/packages, delete cloned repositories, or remove controller home SSH aliases/keypairs or AO state under the controller's home state directory. Local cleanup skips hidden files. Remote deletion is not a restoration of preexisting account/event/description/config values. Custom AO profile paths are not fed to `collect_tcp_ao_auth_cleanup_commands`; it reads the two fixed profile filenames, so profile-driven reference cleanup can miss custom profiles. Sources: `lib/qkd/clean.py:25`, `lib/qkd/clean.py:85`, `lib/qkd/clean.py:429`, `lib/kme/destroy.py:13`, `lib/qkd/bgp_tcp_ao.py:15`, `lib/qkd/ldp_tcp_ao.py:15`, `lib/common/script_user_bootstrap.py:262`, `lib/common/script_user_bootstrap.py:310`.
